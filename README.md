# 迷路ジェネレーター (Maze Generator)

実際のページ.
https://k518-2026.github.io/meirotukuru/

ブラウザ上で動作する、カスタマイズ可能な迷路生成・解析Webアプリケーションです。
外部ライブラリ（jQueryやReactなど）を一切使用せず、バニラなHTML / CSS / JavaScriptのみ、かつ単一ファイルで完結するように設計されています。

## ✨ 特徴 (Features)

* **リアルタイム生成**: 行（縦）と列（横）のスライダーを動かし、好みのサイズの迷路を即座に生成できます（5x5 〜 100x100マスまで対応）。
* **3段階の難易度調整**:
    * **初級**: 壁を間引くことで複数の正解ルート（ループ）を持たせ、行き止まりを減らした迷路。
    * **中級**: 標準的な「完全迷路（Perfect Maze）」。すべてのマスが繋がっており、正解ルートは1つだけです。
    * **上級**: 深さ優先探索の性質を強く残し、より長く複雑な分岐を持つ迷路（※現バージョンは中級をベースに構築）。
* **正解ルートの表示**: トグルスイッチ一つで、スタートからゴールまでの最短経路を青いラインで可視化します。
* **画像として保存**: 生成した迷路を、ワンクリックでPNG画像（背景白・透過なし）としてダウンロードできます。

## 🛠 技術スタック (Technologies)

* **HTML5**: セマンティックなマークアップ（`<main>`, `<aside>` などの活用）。
* **CSS3**: Flexboxを用いたレスポンシブなレイアウト、CSS変数（カスタムプロパティ）によるテーマカラー管理。
* **JavaScript (ES6+)**: クラス構文を用いたオブジェクト指向設計、Canvas APIによる高速な描画処理。

## 🧠 アルゴリズムの設計思想 (Core Algorithms)

本アプリは、パフォーマンスと堅牢性を重視して以下のアルゴリズムを採用しています。

### 1. 迷路の生成：反復的バックトラック法 (Iterative Recursive Backtracker)
迷路の生成には「穴掘り法（DFSベース）」を採用しています。
一般的な再帰関数（Recursive）を用いた実装はコードがシンプルになりますが、巨大な迷路（例: 100x100マス）を生成した際、ブラウザのコールスタック上限を超えてエラー（Stack Overflow）になるリスクがあります。
そのため、本アプリでは**明示的に配列をスタックとして利用する「反復的（Iterative）」なアプローチ**を採用し、どれだけ大きな迷路でもクラッシュしない堅牢な設計としています。

### 2. 正解ルートの探索：幅優先探索 (Breadth-First Search: BFS)
スタートからゴールまでの経路探索には、BFSを採用しています。
深さ優先探索（DFS）でもゴールに到達することは可能ですが、「初級」難易度のようにループ（複数の抜け道）が存在する迷路の場合、DFSでは遠回りの経路を選んでしまうことがあります。BFSは**あらゆる条件下で必ず「最短経路」を導き出せる**ため、経路可視化のロジックとして最適です。

## 🚀 使い方と導入方法 (Getting Started)

単一のHTMLファイルで完結しているため、複雑な環境構築は不要です。

### ローカルでの実行（手元ですぐに試す場合）
1.  リポジトリのコードをダウンロード、またはテキストエディタにコピーして `maze.html` という名前で保存します。
    * **注意**: 保存する際は、必ず文字コードを **UTF-8** に設定してください（Shift-JIS等で保存すると、日本語メニューが文字化けします）。
2.  保存した `maze.html` をダブルクリックして、Google ChromeやSafariなどのモダンブラウザで開きます。

### Web上へのデプロイ（世界中に公開する場合）
初心者の方には、無料で利用できる **GitHub Pages** がおすすめです。
1.  GitHubで新しいリポジトリを作成します。
2.  作成した `maze.html` を `index.html` にリネームしてプッシュします。
3.  リポジトリの `Settings` > `Pages` から、Sourceを `main` ブランチに設定して保存します。
4.  数分後、発行されたURLにアクセスするとアプリが公開されています。

## 💡 カスタマイズのヒント (Customization Tips)

開発者向けに、改修しやすいポイントをまとめました。

* **テーマカラーの変更**:
    CSSの先頭にある `:root` 疑似クラス内の変数を書き換えるだけで、アプリ全体の色調を簡単に変更できます。
    ```css
    :root {
        --primary-blue: #ff6b6b; /* 青色を赤系に変更 */
    }
    ```
* **セルのサイズの変更**:
    JavaScriptコード内の `App.state.cellSize = 20;` の数値を変更することで、1マスあたりのピクセルサイズを変更できます。

## ⚠️ 初心者が見落としやすい注意点 (Common Pitfalls)

* **Canvasの解像度**: Canvas APIでの描画は、HTMLやCSSでサイズをパーセント指定すると画像がぼやけます。本アプリのコード（`renderMaze` メソッド内）のように、必ず JavaScript 側で `canvas.width` と `canvas.height` に対して**ピクセル単位で明示的な数値を代入**してサイズを確定させてから描画を行ってください。
* **外部画像の利用とTainted Canvas**: 将来的に、スタートやゴールのアイコンを外部の画像ファイル（URL）から読み込んでCanvasに描画しようとした場合、ブラウザのセキュリティ機能（CORS）によってCanvasが「汚染状態（Tainted）」と判定されることがあります。この状態になると、`toDataURL()` を使った画像ダウンロード機能がブロックされエラーになります。画像を組み込む際は、Base64形式でコード内に直接埋め込むか、適切なCORS設定がされたサーバーから画像を配信する必要があります。
